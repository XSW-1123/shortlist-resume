# Phase 0 信息采集规程

目标：在动笔前拿到「写得出、且经得起追问」的最小完备事实集。原则是先问后写、分轮问、不替用户填答案。

## 采集方式

1. Copy `assets/intake.form.md` 到工作区，作为唯一填写表。
2. 分 2–4 轮提问，每轮最多 4 个问题；优先用结构化选项题（可多选时说明），开放题留给项目与数字。
3. 第一轮只问最硬的 4 项：目标岗位与 JD、教育背景硬指标、主项目、联系方式。用户答完再问下一轮，不要一次甩 40 个字段。
4. 用户说「没有 / 不清楚 / 你看着办」时，把该字段标 `[需确认]` 并在表格里保留空位；**不要推断、不要编、不要用行业平均值填**。
5. 用户提供的项目源码路径，要实际打开核对关键实现与注释，再写进证据库；不能只凭口述认定「用了某技术」。
6. 采集结束时把表格回读一遍，显式列出仍为 `[需确认]` 的字段并交给用户确认。硬性字段（姓名、学校、学历、毕业时间、目标岗位、至少一个同栈项目）未解决前不进入 Phase 3。

## 字段清单

### A. 硬性字段（缺一不可）

| 字段 | 用途 | 校验点 |
|---|---|---|
| 姓名、电话、邮箱、可选 GitHub / 主页 | 页眉 | 电话按 `138-0000-0000` 分段显示，不擅自改号 |
| 求职意向（岗位全称） | `intent`、文件名 stem | 与 JD 岗位名逐字一致 |
| 到岗时间 / 可实习时长 / 城市 | `availability` | 与教育背景的毕业时间不冲突 |
| 学校、学历、专业、入学—毕业 | `education` | 时间和届别自洽，不写政治面貌 |
| GPA / 排名 / 奖学金 | 首屏硬指标 | 有排名才写 GPA；只有 GPA 没有排名要提示用户补 |
| 目标 JD 原文（或明确「无 JD」） | Phase 1 考点清单 | 无 JD 时必须在 report 写明按哪个基线 |
| 至少 1 个与目标岗位同技术栈的项目 | `projects` | 需要源码路径或可核验材料位置 |

### B. 项目深挖字段（每个项目一组）

- 一句话定位、类型（原创 / 实习 / 横向课题 / 科研）、起止时间、本人负责的模块
- 技术栈（逐项确认真实使用过，不是「了解过」）
- **最大难点 2–3 条**：当时的问题 → 选了什么方案 → 为什么不选另一个方案 → 边界与代价在哪
- 可核验数字：每项都带「怎么测的 / 从哪条命令或哪份文件数出来的」
- 源码位置：文件路径 + 行号，作为 R7/R17 的出处
- 是否部署、是否开源、仓库可见性（没有就不写「已上线」）

### C. 可选字段

- 实习经历（有则单独成 `实习经历` 板块，仍用标准板块名）
- 英语等级、竞赛奖项、奖学金次数、论文 / 软著状态、横向课题成果
- 证件照文件（没有就不留空框）
- 目标城市优先级、期望薪资（一般不写进简历）
- 既往投递版本、被面试官问倒过的问题（用于回流加强）

### D. 跨方向经历归类（必做）

把用户列出的所有经历按目标岗位技术栈分成三类，并在 `report.md` 记下每条的去向：

1. **整块删除**：与目标岗位不同栈的项目（例如投后端时的算法 / 科研 / 前端 / 硬件项目），不得作为并列项目出现，也不得标个语言标签保留。
2. **教育背景下 1–2 行略写**：奖项、论文、软著、横向课题的事实性名称，用行内标签，不带争议数字、不展开 bullet、不自造板块标题。
3. **仅面试口述**：真实但不该占版面的细节，写进面试准备材料，不进简历。

用户说「其他经历也可以加，但要略写」时走第 2 类，且 `项目经历` 板块一字不让。

## 数字口径检查

采集完立刻做一次：同一事实是否出现两套数字（例如同一批报告既说 18 份又说 95 份、同一图谱既说 288 张又说 941 张）？出现就把整组标为「口径冲突，待用户确认最终口径」，确认前不写进简历，也不取平均、不挑一个。

## 结束条件

表格中没有未解决的硬性字段，`evidence/` 有每条数字的出处，跨方向经历已归类，`report.md` 里写明了「哪些信息缺失、因此哪一行没写」。满足后才进入 Phase 1。
