# Phase 4 对抗式复核清单（挑刺面试官视角）

用法：把定稿文本与目标 JD 放在面前，逐条作答。**只挑刺，不夸奖**。每条给出「位置 + 判定 + 修改动作」。任何一条判不通过，回到 Phase 3，不带着问题渲染。

## 初筛与首屏

1. 7 秒内从简历里读到的三个关键信息是什么？其中几个与 JD 直接相关？有一个与岗位方向无关就直接判不通过并指出位置。
2. 首屏有没有关键词、数字、做过真东西的证据？还是只有课程、自我评价、业务流程描述？
3. 顶部有没有置顶自我评价 / 个人优势占首屏？是否与教育背景或项目描述重复？

## 项目板块（一票否决区）

4. `项目经历` 板块是否 100% 与目标岗位同技术栈？有没有并列的其他方向项目，哪怕只写了 1–2 条？有没有标个语言标签就当作处理过了？项目板块岗位相关字符占比是多少？低于 100% 不通过。
5. 非岗位技术词扫描按板块计：逐字列出跨语言、前端框架、算法模型、论文、竞赛科研等无关技术名 / 项目名 / 成果名。项目板块命中数须为 0；`教育背景` 略写行允许事实性名称命中，两个数字分开给。
6. 逐行审计：把简历按行拆开，逐行判断「这一行能被追问出哪个目标岗位的技术细节」。列出所有答不上来的行，重点查主修课程罗列、业务流程叙述、工作总结式 bullet（跑通全链路 / 按 N 域拆表）、置顶自我评价、政治面貌、重复的城市信息。项目板块内弱相关行命中数须为 0。
7. 删掉无关内容后有没有为填满版面塞水货？版面是靠真实考点撑起来的，还是靠形容词 / 重复内容 / 过大的空白？底部留白是否超过页高 15%？
8. 项目板块占全文多少行 / 多少字符？是否 ≥ 60%？`教育背景` 略写行是否 ≤ 10% 且不含项目头、技术栈行、desc、展开 bullet 或争议数字？

## bullet 质量

9. 哪一条 bullet 你会在面试中追问？列出会问的 5 个问题，按深度排序（实现细节 → 常见问题 → 方案对比 → 为什么不用 B → 数字怎么测的）。
10. 哪一条 bullet 看起来像 AI 生成的、或者任何申请者都能写？逐条判定是否走了 PQR（前半句有无问题或约束，后半句有无结果或明确边界）。
11. 每条 bullet 是否至少有一处「为什么这么选 / 边界在哪 / 代价是什么」，还是通篇只有完美方案？功能清单等于告诉对方这是教程项目。
12. 逐条量出字符数并数渲染行数，列出超过 2 行的条目（中英混排时 100–120 字符仍可能落在 2 行，字符数只作参考）。
13. 有没有把「多少个类 / 接口 / 表 / 页面」这类体量计数当成成果写？全篇这类计数是否超过 2 个？结果数字是否优先于规模数字？
14. 一条 bullet 是否塞了 4 个以上机制、导致面试官无从下口？指出该拆成哪两条，且不许新增事实。
15. 项目 bullet 里有没有残留「参与 / 协助 / 负责」「显著提升」「效果良好」这类弱动词与空结论？

## 技能栏与技术词

16. 专业技能是否 6 条左右、只留岗位刚需、含该岗位的地基类技术？有没有混入跨方向技术栈、有没有「精通」、有没有堆成一整页？
17. 技能栏是否保留「熟悉 / 理解 / 了解 / 掌握」的诚实分级，且同一条内不自相矛盾？
18. 技能栏里有没有实现级细节词（某个 SQL 子句、某个 Lua 脚本、某个注解名、某个回调钩子）？这些应该只在项目 bullet 出现一次。有没有同一机制两处各写一遍、让整页像重复的名词清单？
19. 有没有技术词只在简历里出现、但项目 bullet 里没有使用场景？列出来。
20. 把技能栏每行、项目每条 bullet 的技术词逐个列出，逐个问「这个词在 P0/P1 清单或 JD 哪一条？在项目源码 / 证据库哪一处有落点？」。答不上来的词就是凑数，直接删。技能第一条是不是该岗位最核心的语言与框架？顺序是否按岗位匹配度而非学习顺序？
21. 难度闸门：对写下的重要技术词做三层追问自测。简历上有没有明显扛不住第三层的词？无证据黑名单里的词命中是否为 0？

## 数字与一致性

22. 有没有任何一处听起来不像真人写的，或任何数字可疑？把可疑数字的测量方式反问出来。全文同一事实是否只有一套数字、有无互相矛盾的两处？
23. PDF 与 DOCX 的板块标题及顺序是否逐字一致？有没有「补充信息 / 其他信息 / 荣誉奖项 / 科研与荣誉」这类自造板块？出现任何一个直接判不通过。

## 交付链路

24. 用户默认打开的 `deliver/` 成品是否与当前推荐版逐字一致？`source.yaml` 是否已同步？旧版是否仍留在 `apps/` 可回滚？匹配分若超过 85%，是内容真的更匹配还是删内容造成的权重区前移？明确回答「是否应该据此继续加词」。

## 结论

按「初筛会不会给面试」给一个明确的 **会 / 不会**，并给出最关键的一条修改。把全部判定写进 `report.md`，再运行 `scripts/validate.py`。
