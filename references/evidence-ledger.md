# 证据台账与交付报告规程

对应 R7 / R12 / R16 / R17。原则：**没有来源的行不许留在简历上**。

## 引用标准（什么算来源）

| 级别 | 形式 | 例子 |
|---|---|---|
| 可核验（必须） | 源码文件 + 行号 | `cache/CacheHelper.java:192-205` |
| 可核验（必须） | 命令输出 / 脚本实测 | `python scripts/validate.py` 的 20 项 OK 输出 |
| 可核验（必须） | 证据库条目 | `evidence/achievements.md` 第 12 条 |
| 可核验（必须） | 完整 URL + 检索日期 | `https://...`（2026-11-14 检索） |
| 可核验（必须） | JD 条目编号 | `jd.md 第 2–7 条任职要求` |
| 不合格 | 「我查过了」「已联网学习」「业内一般」「据经验」 | 一律退回重找 |
| 不合格 | 只有截图没有文字定位 | 补文件行号或命令输出 |

`evidence/numbers.md` 每条数字必须写清：数值、单位、测量方式、测量日期、原始出处。例：`83 个 REST 接口｜统计 @RequestMapping / @GetMapping 等注解数｜2026-11-14｜MealNow/MealNow 源码全量扫描`。自测或造数测出来的算真实，但要写明是本地测得、不是线上 QPS。

## `report.md` 结构

```
# 投递报告 · <日期> · <版本>

## 0. 本版假设与目标
- 目标岗位 / JD 文件 / 无 JD 时采用的基线
- 相对上一版改了什么、为什么改、哪些内容经复核后保持不改

## 1. 信息采集结果
- 仍为 [需确认] 的字段及因此没写的行
- 跨方向经历三级归类表（删除 / 略写 / 仅面试口述，逐条给去向）

## 2. JD 拆解
- 四桶表（带条目编号）、Top 12 关键词、P0/P1 清单及权重来源
- 每个 P0 词的三层追问链
- 主动放弃的 JD 关键词及原因；无证据词黑名单

## 3. 逐行证据台账（必交）
| 行 | 内容 | 来源（URL / 文件行号 / 命令输出） | 面试官权重 | 项目证据 | 三层追问链 |
|---|---|---|---|---|---|
| 页眉 | … | … | … | … | … |
| 教育背景 1 | … | … | … | … | … |
| 技能 1..N | … | … | … | … | … |
| 项目标题 / 技术栈 / desc | … | … | … | … | … |
| bullet 1..N | … | … | … | … | … |

台账不许有空来源行；一行一个可追问考点。

## 4. 逐行审计与弱相关行处置
| 原文 | 判定 | 处置 | 理由 |
|---|---|---|---|

## 5. 版式实测
1 页 / 文本层 / 页数 / 替换符数 / 板块顺序（PDF + DOCX）/ 项目板块字符占比 /
底部留白 / bullet 最长渲染行数 / 页边距 / 字号 / 行距 / 孤字与重叠

## 6. 校验结果
scripts/validate.py 的完整输出与退出码；匹配分（如测）及归因说明

## 7. 交付链路
deliver/ 四件产物与 apps/<version>/ 的字节比对结果、source.yaml 比对结果、
旧版归档位置
```

## 台账填写要点

- 技能栏每行标注「权重来源 + 项目出处 + 程度词梯度 + 三层追问链」，并列出技能栏里残留的实现级细节词（应为 0）。
- 项目每条 bullet 标注：对齐哪个 JD 关键词、权重来源、源码 / 证据库出处、「为什么 / 边界 / 代价」写在哪一句、P/Q/R 分别在哪一句、字数、实测渲染行数。
- 主动放弃的关键词逐个给原因；无证据词命中数须为 0。
- 匹配分不是优化目标；若掉分或涨分，逐词 diff 归因并写明是脚本口径效应还是内容变化，据此决定是否回调（通常不回调）。

## 与校验器的分工

`scripts/validate.py` 只机器核验可观测项（页数、文本层、板块顺序、占比、留白、行数、词表、交付链路一致性、报告存在）。**它不能证明内容真实**；真实性由本文件的台账和人工逐行审计负责。两者都过才算交付。
